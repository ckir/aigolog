# B2a: patterns and the report. Implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `aigolog analyze` mines every record into a pattern with typed slots, stores the patterns and the slot values, and prints a report with no model: the source summary, the digest and the full summary (a no-model run always prints it; `--summary` is accepted), or with `--json` the same content as one JSON document. The open items of `TODO.md` are closed first.

**Architecture:** A new package `internal/miner` turns the text of a record into a pattern and its values, in two passes (the first learns while the records are read, the second reads them back from the store and assigns). The store gets a second layout (schema 2: `patterns`, `slots`, `slot_values`, and two columns of `records`), written in chunks, with the indexes made after the load. A new package `internal/summary` builds the summary and the digest from queries; a new package `internal/report` renders them as text or JSON. The eight questions, `query` and `show` are sub-project B2b and are not here.

**Tech Stack:** Go 1.27.4 (module floor `go 1.26.0`), the standard library, `modernc.org/sqlite` v1.62.0, `golang.org/x/sys`. No new module.

**Spec:** `docs/superpowers/specs/2026-11-15-engine-and-report-design.md`, sections 7.3 (540-571), 7.4 (573-625), 7.5 (627-655), 7.10 (822-841), 7.11 (843-864), acceptance A2 (929-950), A7 (992), A10 and A11 only as tripwires (not built here). The roadmap is `docs/superpowers/plans/2026-11-16-part-1-roadmap.md` (B2 was split into B2a and B2b on 2026-11-17, the owner's choice). B2a is written against `main` at `99d0c8c` (B1 merged); every file and line named below was read on that commit.

**Decided before this plan, by the owner (2026-11-17):** B2 is two sub-projects, each with its own branch, pull request and plan. The open items of `TODO.md` are the first task of this plan. The values table is a plain table whose indexes are made after the load (not `WITHOUT ROWID`).

## Global Constraints

- Go toolchain 1.27.4 on the development machine and in the workflow; `go.mod` says `go 1.26.0`. `CGO_ENABLED=0`. Targets: linux and windows, amd64 and arm64. Windows x64 and ARM64 run the whole suite in CI on every push.
- Third-party modules: `modernc.org/sqlite` v1.62.0 and `golang.org/x/sys` only. The miner is written here, in the standard library.
- The gate is `just check` (`fmt-check`, `vet`, `vet-cross`, `license-check`, `test`), run on the development machine and on ubuntu-24.04, windows-2025 and windows-11-arm. The repository is public: no machine-specific path, name or address in a file or a commit message.
- Every Go file starts with the header of `source-header.txt` (`just license` adds it).
- Exit codes (roadmap decision 4): 0 done, 1 failed, 2 wrong usage, 5 the store cannot be written. B2a adds no code.
- Text that comes from a log reaches the terminal only through `internal/textsafe.Clean`. A value from a log is never part of the text of a query: it is a parameter. A command shown to the user never contains log text.
- Same input, same output: no map iteration, clock, random number or goroutine order may reach a pattern, a value, a summary or a report.
- Memory use must not grow with the size of the input (design 7.4). Records and values go to disk in chunks.
- Tests need no network. A test that needs the fetched sshd sample is skipped with a visible notice when the file is absent (A3's rule); CI fetches it.
- Commit trailer `Co-Authored-By: <the implementer's model name> <noreply@anthropic.com>`. Commit and push only when the owner says so.

## Review Focus

Inputs and conditions the design implies and no task would otherwise exercise, most likely first. Each has its test in the task named.

1. A log in which almost every line is different (a debug log with ids and free text): the number of patterns must stop at the cap, the rest must go to the catch-all, memory must stay bounded, and the summary must still fit its budget and say how many patterns it left out. (Tasks 4, 6, 8)
2. A value that is hostile or huge: escape sequences, shell syntax, text that tells the reader to report nothing, a 1 MiB token. The digest must show it cut and escaped, the report must carry no raw control character, and the stored value must be bounded. (Tasks 3, 8, 9)
3. A record that is only a time stamp, an empty record, a record of one token, a record of more than 256 tokens, and a record whose text is in another script: none may panic, loop or make a pattern with a wrong number of slots. (Tasks 3, 4)
4. Two sources in one run, one with stamps and one without, sharing patterns; and a run with `--no-keep` (the report must be built before the database is removed). (Tasks 6, 9)
5. A run that stops while it mines (a signal, a failing disk) leaves a database that is not complete and is removed as before; a database of schema 1 left in the cache folder by B1 is refused by `Open`, shown by `list`, and removed by age or by `clean`, never read as schema 2. (Tasks 5, 6)

## Calls this plan makes

Each is mine, to be checked by the owner. None is the design's text.

| # | Call | Why |
|---|---|---|
| 1 | The miner reads `Raw[Stamp.Len:]`: the reader records how many bytes at the start of a record its time stamp (with a priority tag and a bracket before it) covers. | The stamp is not part of the message; without the length the miner would make slots of the digits of the time. `Parse` already knows where the stamp ends. |
| 2 | Typed values (whole number, decimal, hexadecimal, IPv4, IPv6, UUID) are found by a hand-written scanner, not by regular expressions. | A scanner with six alternatives built from `regexp` was estimated at tens of microseconds a line; 655,146 lines would take about a minute for the masking alone. Not measured; the scanner is the plain choice and the tests pin its rules. |
| 3 | The clustering is Drain-style with depth 6 (the tree path is the number of tokens and the first four tokens), similarity 0.5, at most 100 children a node, at most 256 tokens a record, at most 1,000 patterns. All five are named constants. | Measured on 2026-11-17 with a throwaway prototype of Tasks 3 and 4 on the sshd sample (host and program take the first two tokens of every line): depth 4 merged `Failed password` and `Accepted password` lines into one pattern, so the design's question 1 (patterns that contain these words) could not find them; depth 6 gave 24 patterns and the design's figures (520 `Failed password` lines in three patterns, 23 addresses, line 956, 286 and 80 attempts for the two addresses, first and last lines 1024 and 1997 for the first); depth 7 gave 71 patterns. The cap is provisional (roadmap: set by B2a on the test logs). |
| 4 | A pattern never changes shape after pass 1; pass 2 matches a record to the most specific pattern whose fixed tokens equal the record's. A record that matches none (only possible past the cap) goes to the catch-all, pattern 0, which has no slots. | Deterministic and consistent: a record that was learned always matches the pattern it was learned into. |
| 5 | Stored values are text, cut at 512 bytes. Numeric statistics cast them at query time. | One column type; the cut bounds the table and a hostile value. |

**Interfaces:**

  - `type Value struct { Type SlotType; Text string }`.
  - `type Token struct { Raw string; Text string; Values []Value }`: `Raw` is the token as written, `Text` is `Raw` with each typed value replaced by its marker and then cut to at most `MaxTokenTextBytes` bytes on a character boundary (so a template never holds more than that of a token), `Values` are the typed values in order.
  - `const MaxTokens = 256`, `const MaxValueBytes = 512`, `const MaxTokenTextBytes = 256`.
  - `func Scan(msg string) []Token`: splits `msg` on ASCII white space (space, tab, newline, carriage return, vertical tab, form feed) into at most `MaxTokens` tokens (the text after the 256th token is ignored here; the record keeps it whole in the store) and masks each.
  - `func CutValue(s string) string`: `s` unchanged when `len(s) <= MaxValueBytes`, otherwise its first `MaxValueBytes` bytes shortened to the last whole UTF-8 sequence.

**The rules of the masking (the tests below are the oracle; where a rule and a test disagree, the test wins and the difference is reported).** A byte is a *word byte* when it is an ASCII letter, a digit, `_`, or any byte of 0x80 or more. A typed value starts at byte `i` of a token only when `i == 0` or the byte before it is not a word byte, and not (a `.` whose own previous byte is a word byte). A value ends where the next byte is not a word byte (or the token ends). At a start, these are tried in order and the first that matches wins: (1) UUID: 8-4-4-4-12 hexadecimal digits with `-`; (2) IPv6: groups of 1 to 4 hexadecimal digits separated by `:`, with either one `::` or exactly eight groups, at least two colons, at most 45 bytes; (3) IPv4: four groups of 1 to 3 digits, each at most 255, separated by `.`, not followed by `.` and a digit; (4) `0x` or `0X` and one or more hexadecimal digits; (5) decimal: digits, `.`, digits, not followed by `.` and a digit; (6) long hexadecimal: eight or more hexadecimal digits that include at least one digit and at least one of `a`-`f` (either case); (7) whole number: one to 18 digits (19 or more are not a value). A token that matches none is plain text.

**Rulings made during execution (2026-11-17, after the review of the first implementation; they amend the rules above):**
- **R6, bounds.** `Scan` guarantees that `len(Values)` equals the number of markers it put into `Text`; `Text` never ends inside a marker; a marker is put in only when `len(Text)+len(marker) <= MaxTokenTextBytes`, and masking of the token stops at the first marker that does not fit or when `Text` is full (the rest of the token is neither masked nor in `Values`; `Raw` stays whole; plain bytes that straddle the limit are cut on a character boundary); a hexadecimal value (either form, `0x` included) longer than 130 bytes is not a value (it falls through the later rules); a decimal longer than 40 bytes is not a decimal (the whole number before the `.` is then tried, so `1.` followed by a megabyte of ones gives `<int>.` and plain text); the scans of digit and hexadecimal runs stop at these caps (no scan of a megabyte for one start). `Text` must not pin the megabyte of its token (build it in a buffer sized to the limit, not to `len(Raw)`). Task 4 counts slots from `Values`, never by parsing `Text` (a log may hold a literal `<int>`).
- **R7, IPv6.** An IPv6 candidate may not start right after a `:`; may not be followed by a `.` and a digit (so `::ffff:1.2.3.4` gives `::ffff:<ip4>`); may not be followed by a `:` that is followed by a hexadecimal digit or a second `:` (a longer chain is not an address); a single trailing `:` is not part of it (`fe80::1:` gives `<ip6>:`). Rows added to the oracle: `fe80::1:` -> `<ip6>:`; `::ffff:1.2.3.4` -> `::ffff:<ip4>`; `a:b:c:d:e:f:1:2:3` -> `a:b:c:d:e:f:<int>:<int>:<int>`; `deadbeef::1` -> `deadbeef::<int>`; `1:2:3:4:5:6:7:8:9::` -> `<int>:<int>:<int>:<int>:<int>:<int>:<int>:<int>:<int>::`.

**The algorithm (the tests below are the oracle):** tokens come from `Scan(msg)`; a message with no tokens is never learned and matches the catch-all. The tree: the first level is the number of tokens; the next `min(Depth-2, n)` levels (four tokens for the default depth of 6; the depth counts the root and the length level as the method does) are keyed by the token's `Text`, except that a token whose `Text` contains a marker, or a digit, or a literal `<*>`, is keyed `<*>`; a node that already has `MaxChildren` children and has no child for a key uses its `<*>` child (made if absent). A leaf holds clusters in order of creation. The similarity of a cluster to a message of the same length is the number of positions where the cluster's token is not `<*>` and equals the message token's `Text`, divided by the length. The best cluster is the one of highest similarity, ties to the lowest ID. When its similarity is at least `Similarity`, the message joins it: each position whose tokens differ becomes `<*>`. Otherwise a new cluster is made, unless `MaxPatterns` clusters exist, in which case the message is counted in the catch-all. The pattern text is the cluster's tokens joined by one space. The slots of a pattern, in order: for each token of the template, a `Word` slot when it is `<*>`, otherwise the types of the typed values of that token as the first message that made the cluster had them. `Match` walks the same tree for the message (a key with no child goes to the `<*>` child; a missing node means no match), and among the leaf's clusters whose tokens other than `<*>` all equal the message's `Text` it takes the one with most non-`<*>` tokens, ties to the lowest ID; no such cluster means the catch-all. Its values are, in token order, the whole `Raw` of the message's token at each `<*>` position, and the typed values of the token at each other position.
